# Проверка глубокой доработки Poster 2.0

Дата: 22 октября 2026. Продолжение `d788f39` в существующей ветке `codex/poster-2-recognition`, PR №2. Начальная реализация не создавалась заново. Исходное задание: `specifications/POSTER_2_DEEP_RU.md`.

## Аудит и изменения

[Подробный аудит](RECOGNITION_AUDIT.md) охватывает detector/forms/knowledge/network/learner/service/capture/runtime/app. Помимо проблем из ТЗ обнаружены повторяющиеся ссылки на одну форму, устаревшие временные селекторы после смены этапа, совпадение числового параметра раздела со значением cookie, привязка авторизации phpBB к User-Agent и необходимость соблюдения времени жизни формы.

Переработаны: многофакторная идентификация и уровни адаптеров; ограниченная структурная навигация; альтернативы полей и открытый Shadow DOM; редакторные API; шесть категорий знания с миграциями/историей/отрицательными свидетельствами; причинный граф запросов; свежие HTML/JSON/header/cookie источники; изоляция одной разрешённой транзакции; CDN без передачи авторизации; сохранение старого ключа; отдельный login; различный второй контент и автосохранение GUI. Подробности и точные границы: [архитектура](recognition_architecture.md).

## Метрики и знаменатели

Артефакт: [полный JSON benchmark](benchmarks/recognition-2026-10-22.json). Корпус имеет фиксированный seed/JSON и SHA256 в отчёте. В нём 11 локалей, в том числе RTL; независимые сочетания меню/иконок/вкладок/динамических областей, light/shadow/SPA и многошаговой формы; девять типов редакторного интерфейса; шесть сетевых вариантов. Это контролируемые составные варианты, а не слепая внешняя выборка публичных форумов.

| Измерение | Результат |
|---|---:|

| Отложенные варианты: discovery, field mapping, browser, HTTP | 37/37 по каждому измерению |
| Из них новые варианты обычных структур | 18/18 |
| Из них ранее не используемые сочетания структур, включая этапы | 19/19 |

| Синтетический engine signature corpus: точное множество технологий | 17/17 |

37 положительных форм прошли без ручного обучения. Необъяснённый nonce из отрицательной группы требует доработки/обучения; отсутствие permalink и login-result оставляют отправку неподтверждённой и запрещают повтор. Нельзя включать эти ожидаемые отказы в положительную метрику как успешный HTTP.

Engine corpus проверяет распознавание контролируемых фрагментов по независимым каналам, включая WordPress + wpForo и ложные признаки внутри пользовательского текста. **17/17 не является точностью на реальных установках CMS**. Равным образом 37/37 не доказывает универсальность интернета. Отложенные варианты отделены от семи исходных примеров, но не являются независимым коммерческим аудитом или статистически репрезентативной выборкой.

## Реальный движок

Запросы HTTP: fresh form GET 200 → POST 302 → independent topic GET 200, title/body verification; SUCCEEDED после закрытия браузера. [Воспроизведение и CI](real_engine_testing.md).

XenForo, vBulletin, MyBB, Discourse, SMF, Invision, Flarum, WordPress/wpForo пока имеют проверенные каналы идентификации на корпусе; HTTP-публикация в их оригинальных установках не заявляется. TinyMCE/CKEditor/Quill API-state проверки используют совместимые тестовые реализации; все версии оригинальных редакторов не проверены.

## CI и оставшиеся проверки

GitHub Actions проверяет Python 3.11/3.13 под Xvfb, отдельную настоящую установку phpBB на Python 3.13/PHP 8.3 и native Windows Recorder/clipboard smoke на Python 3.13. Linux runner закреплён на Ubuntu 24.04 для стабильной установки поддерживаемых Playwright зависимостей; плавающий ubuntu-latest не используется. Актуальный статус относится к конкретному head PR №2; локальные результаты не подменяют CI.

Следующие подтверждения для публичных установок: другие оригинальные CMS и версии, сторонние темы/плагины/редакторы, разные права пользователей, SSO и срок жизни сессии, сетевые сбои и модерация на собственных разрешённых стендах. Закрытый Shadow DOM, cross-origin SSO/iframe, произвольные JS-токены, файлы и повторяющиеся поля остаются ограничениями. Антибот/CAPTCHA/доступ/модерация не обходятся. До выполнения этой автоматической проверки пользователю не предлагались публичные тестовые публикации.
