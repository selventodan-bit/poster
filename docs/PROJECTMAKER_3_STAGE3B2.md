## HTTP-контракт

HTTP.Request/Get/Post/Download используют одну реализацию httpx; SetHeader/SetCookie/
ClearCookies управляют изолированной сессией запуска. Браузер для HTTP не запускается.
TLS включён, системные proxy/env не наследуются, автоматических повторов нет.
GET/HEAD перенаправляются до 10 раз; write-preserving 307/308 не повторяют отправку;
перенаправление HTTPS → HTTP запрещено. Пользовательские заголовки не переносятся
на другой origin. Cookie jar соблюдает domain/path/secure.

Типы тела: none/json/form/multipart/text. Multipart files — поле → относительный путь.
Результат: status, headers, cookies, bytes, text, json, необязательный path.
`expected_status=[]` принимает любой статус. Таймаут общий для цепочки redirect,
включая чтение ответа. Ограничивается декодированный размер (включая gzip).
По умолчанию тело ответа защищено; для открытых данных явно снимите protect_response.
Cookies и известные секретные поля дополнительно защищаются. В логах нет payload/URL
с токенами, текстов сетевых исключений или секретных заголовков. Ошибки имеют отдельные
коды HTTP_TIMEOUT/CONNECT/NETWORK/STATUS/DECODE/RESPONSE_LIMIT/WRITE_UNKNOWN.

## Общий контракт выполнения

Новые действия регистрируются в существующем Registry, получают параметры Pydantic,
имеют русские подписи/описания и возвращают JSON-результат. SecretRef раскрывается
только для действия; taint защищает его результат. Индексы начинаются с нуля.
Граф никогда не выполняет Python eval/exec. Лимиты host-owned: время 300 с по умолчанию,
шаги ограничены max_steps родителя, включая подпроекты; значение/результат до 1 MB,
совокупные результаты до 16 MB, файл до 10 MB. Ошибки не содержат исходных payload.

## JSON и списки

JSON Pointer соответствует RFC 6901: корень `""`, `/a/0`, экранирование `~0`/`~1`.
Get требует существования пути. Set заменяет корень/элемент или создаёт ключ объекта;
родитель должен существовать, `-` добавляет в конец массива. Delete корня возвращает
null. Merge рекурсивно объединяет объекты (deep=false — только верхний уровень),
массивы заменяются целиком. NaN/Infinity и чрезмерные структуры не допускаются.

Lists — функциональные операции: результат `value`, исходный список не изменяется;
для обновления переменной сохраните `value` обратно в неё. Индексы с нуля; Insert
разрешает индекс длины, остальные требуют существующего индекса. Remove удаляет
по индексу. Unique/Contains сравнивают канонический JSON с сохранением различия
boolean/number, Unique сохраняет порядок. Shuffle принимает воспроизводимый seed.
ForEach использует снимок списка и сохраняет защиту элементов SecretRef.

## Рабочий каталог и файлы

`poster maker-run graph.postergraph.json --workdir ./run-data` явно выбирает каталог.
Без --workdir создаётся отдельный каталог `poster-run-*` в temp: параллельные запуски
не разделяют файлы; путь возвращается в отчёте. Результаты не удаляются при close.
CLI --allow-external-files явно разрешает внешний доступ, JSON графа этого разрешения
дать не может. Относительные пути переносимы, разделители нормализуются; абсолютный
Windows-путь не интерпретируется как Linux-путь. Проверяются .., symlink и Windows
reparse points. Корень sandbox нельзя удалить/перезаписать. Защита рассчитана на
операции графа, не на враждебный внешний процесс, одновременно подменяющий каталоги.

WriteText/Copy/Move/HTTP.Download по умолчанию не перезаписывают файлы. Запись через
временный файл и атомарную публикацию; AppendText перечитывает и атомарно заменяет
файл, сохраняя BOM. Delete удаляет только файл или пустой каталог, не дерево.
Move между томами выполняет ограниченное копирование и удаление источника после
успешной публикации; при ошибке удаления остаются обе копии. Максимум 10 MB на файл,
100 MB записей за запуск с подпроектами, 10000 элементов каталога. Кодировку задаёт
пользователь; тексты с секретами помечайте «Защитить результат».

## Таблицы, CSV и Excel

Таблица — обычное JSON-значение `{columns:["name","n"],rows:[["a",1]]}`, отдельно от
SQLite. До 256 уникальных непустых имён, 10000 строк, 100000 ячеек и 1 MB JSON.
FromJSON принимает массив объектов (пропуски → null) или таблицу, ToJSON возвращает
массив объектов. FindRows возвращает индексы; Filter — новую таблицу. Для обхода
JSON.Get `/rows` → ForEach. Результаты операций функциональные, исходник не меняется.

CSV поддерживает UTF-8/BOM, запятую/точку с запятой/tab, заголовки и многострочные
значения. По умолчанию CSV — строки: у формата нет типов. infer_json=true явно
включает распознавание JSON-ячеек; пустая ячейка остаётся пустой строкой, null при
записи становится пустой ячейкой. Заголовки без header получают column_1… .

XLSX: openpyxl (MIT), et-xmlfile (MIT), defusedxml (PSF). Формулы **не вычисляются**:
Read использует сохранённый cached value, при его отсутствии null. Новые строки
начиная с `=` пишутся именно строками, не формулами. Даты читаются ISO-строками;
объекты/массивы записываются JSON-текстом. Для изменения существующей книги требуется
update_existing=true, для замены листа отдельно replace_sheet=true. Другие листы
сохраняются. Книги с макросами, рисунками, external links, pivot/ActiveX/unsupported
extensions не обновляются, чтобы не потерять неподдерживаемые данные. Проверяются
размер ZIP и суммарный XML (20 MB); запись атомарная, исходник до успеха не меняется.

## Подпроекты

Project.Run ищет относительный путь рядом с файлом родительского графа. Исходный
каталог верхнего графа — отдельная read-only capability для дочерних JSON и их
зашифрованных sidecar; .. разрешён только внутри этого корня. Файлы данных работают
в выбранном workdir, а не рядом с исходниками. Без project_path пути подпроектов
считаются относительно workdir. Дочерний граф объявляет выходы в
`extensions.outputs=["result"]`; кубик может запросить только их подмножество.
Возвращается `{outputs:{result:...},status:"SUCCEEDED"}`. Локальные переменные и
HTTP cookie jar не разделяются. Защищённые входы/выходы переупаковываются в Vault
соответствующего запуска, с сохранением JSON-типов.

Используется тот же GraphRunner/Registry, общие шаги, deadline и лимит записей.
Глубина до 8 графов, повтор пути в стеке запрещён. Stop отменяет активный дочерний
запрос и дожидается закрытия HTTP-клиента. Ошибка ребёнка идёт в Error родителя,
с безопасным child_code. Лимиты всего запуска нельзя обойти Error-переходом.
Подпроекты исполняются batch без интерактивных дочерних breakpoint; breakpoint
на Project.Run остаётся доступен. Browser.* и браузерный Logic.If внутри ребёнка
отклоняются: контракт совместной живой браузерной сессии здесь не вводится.

## Дополнительные границы

Новые GraphRunner-запуски имеют независимые variables/cookies/default workdir.
Вложенные графы наследуют workdir осознанно, но не переменные/cookies. Выбранный
один и тот же каталог между параллельными независимыми запусками — явное разделение
файлов; для изоляции выбирайте отдельные каталоги (по умолчанию они отдельные).
Нет синхронизации HTTP jar с browser storage. Full GUI сам использует Qt WebEngine;
утверждение «без браузера» относится к исполнению графа: browser session не стартует.
Независимый Runner действительно не импортирует Playwright и не создаёт его процессов.

Объект точной формы {"secret_ref":...} зарезервирован существующим протоколом v2;
JSON.Parse и внешние HTTP JSON-ответы отклоняют такую форму вместо принятия её за
право читать Vault. JSON с NaN/Infinity не принимается. Ключи и профили не экспортируются.
Заголовки ограничены 64 KB/100 именами, cookies — 1000; Vault — 24 MB шифротекста.

Следующий этап: отдельный контракт browser/HTTP cookies и browser-подпроектов,
постраничный просмотр больших данных и улучшение диагностики. Новый Dispatcher,
Molab, планировщик и произвольные Python-плагины здесь не добавляются.

## Стабилизация после 7ebc444

- Примеры включены в wheel как package data; исходные standalone JSON и ресурсы
  пакета проверяются на побайтовое равенство. Путь не зависит от checkout/cwd.
  Проверена обычная, не editable установка wheel с полным Qt-сценарием.
- Timeout-тест разделяет допуск POST сервером и чтение тела: сервер подтверждает
  приём и держит тело на Event; короткий read timeout применяется после соединения.
  Отдельно проверяется общий таймаут до отправки (0 серверных вызовов, 1 транспортная
  попытка). В обоих случаях клиент закрывается, повтора POST нет. Диагностика
  различает connect/pool/read/write/total без записи payload.
- Для перекрывающихся копий на 1200-узловом графе Windows E2E использует реальный
  поиск + Enter и подтверждает выделение/удаление именно копии после Undo/Redo.
- Qt задаёт arrowType кнопкам вкладок только после polish/show. Имена кнопок
  прокрутки определяются по исходным именам Qt; невидимые вкладки не публикуют
  ложные координаты. Проверены клики в обе стороны при минимальном размере окна.
- После закрытия на «Система» восстановление layout не прячет Maker toolbar при
  следующем запуске. Имя прежней страницы хранится только в локальных настройках.
- Observer сохраняет прежнюю атомарную публикацию JSON. Чтение кратковременного
  sharing violation повторяет только чтение; пользовательские действия/POST не
  повторяются. Lite публикует run_graph_id: ожидание не принимает SUCCEEDED от
  предыдущего графа за результат нового.
- READ_ONLY — стартовая диагностическая отметка RecognitionSession, не доказательство
  запрета конкретного клика. Для CLICK_FAILED теперь публикуются безопасные class/hint,
  read_only и write_admitted. Причину прежнего одиночного эпизода по старой записи
  только с кодом восстановить нельзя; он не объявляется исправленным без повторного
  наблюдения. Ограничения отправки, click timeout и отсутствие повторной записи не менялись.

Windows GUI сохраняет HTTP/JSON, Lists/Files, CSV/XLSX и родительский граф, а также
передаёт используемый дочерний JSON. Artifact maker-windows-data-graph содержит эти
пять физических файлов. Отдельный Linux job исполняет каждый сохранённый граф в
свежем CLI без Qt/Tk/Playwright. Для HTTP поднимается контролируемый сервер на
**том же** сохранённом loopback-порту; JSON/URL не переписываются. Сравниваются SHA256
всех файлов до/после. CSV/XLSX проверяют обратное чтение, Project.Run — явные выходы.
Новые операции входят и в Windows Python 3.11/3.12/3.13 pytest-матрицу. Counts/JUnit,
GUI-скриншоты, отчёты CLI и измерения ZIP публикуются CI на SHA проверяемого коммита.
