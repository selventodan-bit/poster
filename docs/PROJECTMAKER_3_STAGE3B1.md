## Выбор интерфейса

| Вариант | Совместимость/стабильность | Размер/поддержка/лицензия |
|---|---|---|
| Qt Widgets + QGraphicsScene + QWebEngineView | Один event loop для всего GUI. Python actor на отдельном asyncio-потоке. Нативное выделение, сцена с пространственным индексом, QSplitter/QDockWidget | В Full Qt уже необходим для браузера. Не нужны Node/npm или второй web-host. LGPLv3 для используемых Qt/PySide модулей; условия и тексты включены |
| Qt браузер + другая UI-модель графа | Подходит при явном адаптере v2; модель Document уже независима от GUI | Выбрана существующая Python Document; UI не исполняет действия |
| React Flow в отдельном QWebEngineView | MIT, развитые порты/масштаб/выделение. Понадобятся JS-сборка, QWebChannel, версионированный мост и второй renderer | Дополнительные зависимости, тестирование мостов и ресурсов в offline ZIP. Не требуется для текущего лимита 2000 узлов |
| FlowGram в WebEngine | MIT, развитые формы и workflow-компоненты. TS runtime не может заменять Python GraphRunner | Ещё больше интеграционных контрактов; в текущем этапе не подключается |
| Tk + отдельный Qt-host | Проверенный этап 3A, сохранён как альтернативный provider и Lite | Не обеспечивает одно окно; не выбран для Full Maker. SetParent не используется |

Реализован первый вариант. BrowserPane и QGraphicsView находятся в одном Qt
QMainWindow; никакого перемещения двух окон рядом или переподчинения HWND нет.
`controller.py` вызывает существующие ActionRecorder, Inspector и GraphRunner.
Поток Qt обслуживает только интерфейс; Playwright/CDP и SQLite живут на asyncio
worker. Связь с нативным браузером — queued Qt signals, без смешивания Tk/Qt.
Обычный CLI не импортирует эти модули.

## Возможности

Сохранены формат v2, загрузка v1 с резервной копией при сохранении, существующая
библиотека действий, порты Success/Error/Switch, логические вкладки, iframe,
popup, normal POST login и encrypted SecretRef. В UI есть библиотека с поиском,
редактирование параметров, переменные и их значения на паузе, запись/продолжение,
шаг/пауза/запуск/стоп, breakpoint, выбранное действие и журнал.

QGraphicsScene поддерживает множественное выделение, drag, copy/delete, undo/redo,
поиск кубика, Ctrl+колесо, перемещение средней кнопкой, именованные порты и
автоматический показ выполняемого узла. Сохраняются координаты и масштаб графа,
положение dock-панелей, геометрия окна и разделитель браузер/граф.

Профили можно создавать, переименовывать, выбирать, явно сохранять, очищать и
удалять. Каждый запуск изолирован; снимки зашифрованы вне каталогов проектов и
Drive. Изменение/удаление активного профиля требует закрытия текущей сессии.

Вкладки Poster 2.0 перенесены на Qt через существующие Workspace, EngineBridge,
RecognitionSession и KnowledgeBase: обучение/распознавание, browser/HTTP-проверка,
READY import/save/retrain, очередь/cancel, запуск/остановка Engine, результаты,
системная диагностика, выбор/явная загрузка Chrome и очистка своих temp-папок.
Старый HTTP Recorder по-прежнему использует установленный Chrome; Maker использует
встроенный браузер. Это явно показано в интерфейсе.

## Версии и проверка обновления

PyPI проверен 24.10.2026: последняя версия PySide6 — 6.12.0. Она установлена и
запущена, а не только указана в lock-файле. API сообщает Qt 6.12.0, базовый
Chromium `140.0.7339.225`, Chromium security patches `152.0.7977.83`, WebEngine
`6.140.0`. Базовый Chromium и уровень backport-патчей — разные значения.
Это не заявление об отсутствии всех уязвимостей.

Для сравнения также реально установлен Qt 6.11.2: Chromium 140.0.7339.225,
security patches 151.0.7922.71. Набор этапа 3A выполняется на новых версиях.
В локальной Debian 13 с X11 over TCP (`DISPLAY=172.17.0.2:99`) и без живой
D-Bus session воспроизведено зависание отдельного host после Inspector/iframe
на 6.11.2 и 6.12.0: destructor WebEngine ожидает pthread condition, затем срабатывает
строгий timeout, exit -9. stderr указывает на недоступный session-bus socket.
Тот же тест с тем же кодом под `dbus-run-session` проходит за 2,4 секунды с exit 0.
Это подтверждённая зависимость Linux GUI-сессии, не отсутствие xcb-плагина и не
повод отключать проверку. На исходном коммите 17/18 jobs тест прошёл также на
Windows и Ubuntu GitHub. Native Linux CI теперь явно владеет своим D-Bus session.
В Linux для исходного Qt GUI используйте `dbus-run-session -- python -m
poster.maker.qt_app` внутри обычной графической сессии либо Xvfb. Обычному headless
Chromium Runner Qt/D-Bus не нужны. Никакой процесс не выдаёт принудительное
завершение за успешное; тест по-прежнему требует exit 0.

## Профили: границы реализации

Cookies и localStorage реально сохраняются и восстанавливаются. sessionStorage
относится к отдельной вкладке и не должен сливаться между вкладками; его экспорт
ещё не реализован. IndexedDB также не заявляется частью снимка. Обычный storage
изолирован приватным Qt-профилем/контекстом в течение выполнения, но snapshot
не является копией полного дискового Chrome-профиля. Секреты и ключи не добавляются
в JSON графа или в Drive. В новом интерфейсе показывается состояние сохранения.

## Проверки и Windows

Lite остаётся на прежней Tk-оболочке с внешним Chrome. Full Maker выбирает Qt UI
через BUILD_INFO и запускается тем же Poster.exe. Пользователю не нужны Python,
Git, Docker, терминал или отдельный запуск сервера. Установка браузеров только
по явному согласию; встроенный Qt уже содержится в явно выбранном Full ZIP.

Нативные тесты проверяют единое окно, 1200 узлов, запись через браузер, параметры,
breakpoint и тот же браузер при продолжении, сохранение v2 и отдельный Linux CLI
с запретом импорта Qt/Tk. Windows E2E отправляет настоящие события ОС; observer
предоставляет только геометрию/состояние, не команды. В него включены popup/iframe
login, профили, XPath, переменные/циклы, старый HTTP путь и проверка дочерних процессов.
Размер и SHA обоих ZIP измеряет упаковщик; наличие EXE само по себе недостаточно.

Для прежнего нестабильного local-test добавлены ограниченные безопасные диагностики
state/stage/codes. Исключения с URL/паролями/ответами не сериализуются. Сбой нужно
диагностировать по этим данным, а не скрывать повторным запуском.
