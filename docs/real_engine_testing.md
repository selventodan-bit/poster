# Настоящий phpBB в изолированной тестовой установке

Стенды MyBB A/B, SMF и Flarum, сравнение переноса знаний и проверка оригинальных редакторов: [актуальная проверка реальных CMS](VALIDATION_REAL_CMS.md). Тест phpBB также загружает экспортированный проект с диска и подтверждает третью публикацию обычным Runtime.

Интеграция использует исходники upstream phpBB 3.3.15, commit `e40d69c54097dcc4e436f3308c75aa39960ada75`, prosilver, SQLite, PHP 8.3. Исходники и зависимости не включены в Poster. Сценарий ограничен loopback; сервер не предназначен для публичного размещения.

В Linux нужны PHP 8.3 с sqlite3/mbstring/xml, Composer 2, unzip и установленный `.[dev,recorder]` с Chromium:

```bash
python scripts/run_phpbb_ci.py
```

Скрипт скачивает фиксированный commit, устанавливает зависимости по upstream composer.lock, создаёт новую базу и случайный локальный пароль, запускает PHP только на `127.0.0.1:8879`, выполняет login → безопасный поиск формы → одну browser-публикацию → закрытие Chromium → отдельную HTTP-публикацию → экспорт READY. Проверки form tokens, прав и ограничений сервера не отключаются. Любой неподтверждённый этап завершает CI с ошибкой. Сервер останавливается в finally.

Все файлы находятся в игнорируемой `.poster/phpbb-ci/`; логин и ключ не попадают в GitHub. Повторный запуск требует нового пустого каталога установки или удаления только собственного предыдущего тестового каталога. Существующие пользовательские проекты не используются.

В облачной сессии PHP запускался в Docker `php:8.3-cli` (digest `sha256:60a100afa8efd88c0f556ce60e891c9bb8b1e8bca15721e4db07eca4fa79c07a`), порт опубликован только на loopback. Зависимости и установка выполнены штатным Composer/installer. После подготовки отдельной локальной установки можно выполнить:

```bash
python scripts/check_phpbb.py --base http://127.0.0.1:8879 --install-config .poster/integration/install.yml --output .poster/phpbb-check
```

Этот тест подтверждает указанную конфигурацию phpBB. Он не подтверждает все версии, расширения, темы, права гостей или другие CMS. Обновления PHP/Composer/upstream dependencies могут потребовать обслуживания интеграционного стенда; это не повод подменять реальный движок имитацией.
