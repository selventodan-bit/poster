# Функциональная матрица ProjectMaker / Poster

Проверка источников: 24 октября 2026 года. Основа Poster — `5bb346132fcef5cd5216658423f5e15852ce2fac`; этап 2 развивается в `codex/poster-3-projectmaker-stage2`. Матрица описывает пользовательские сценарии, без копирования интерфейса, графики, закрытого кода или формата ZennoLab.

Прямые страницы `docs.zennolab.com` и Atlassian в данной среде отвечают через прокси `403 Forbidden`. Найден и прочитан **официальный репозиторий [ZennoLab/docs](https://github.com/ZennoLab/docs)**, содержащий исходники этих страниц и ссылки `targetUrl` на прежнюю документацию 7. Исходники не включаются в поставку Poster.

Основные прочитанные источники:

- [Конструктор и XPath](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Browser_Window/Action_Constructor_and_XPath_Search.mdx): выбор элемента, атрибуты, поиск, выполнение и извлечение данных.
- [Редактор проекта](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Project-editor/Project_Editor.mdx): библиотека, свойства, вкладки проектов и статические блоки.
- [Окно переменных](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Program-interface/Variables_Window.mdx), [циклы](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Recording-and-creating-projects/General-information/Loops.mdx), каталог Logic/Http/Data/Tables в том же репозитории.
- [Запуск отладки](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Debugging%20projects/Starting_Debugging.mdx), [актуализация действий](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Debugging%20projects/Re-recording_Problematic_Sections.mdx), [трассировка](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ProjectMaker/Debugging%20projects/Project_Tracing.mdx).
- [Настройки исполнения ZennoPoster](https://github.com/ZennoLab/docs/blob/main/docs/ZennoPoster/ZennoPoster/Project_delivery/Project_settings/Settings.mdx): повторения, потоки, приоритеты, прокси и изоляция данных.

«Есть» ниже означает реализованную функцию Poster; это не заявление о полном соответствии продукту ZennoLab. Подробные воспроизводимые проверки описаны в [отчёте этапа 2](PROJECTMAKER_3_STAGE2.md).

| Возможность | Poster после этапа 2 | Существующая основа / дальнейший этап |
|---|---|---|
| Интерактивный редактор графа | Есть: добавить, двигать, удалить, копировать, undo, координаты, стрелки Success/Error | Сохранён Tk Canvas этапа 1; расширены порты Switch |
| Библиотека и свойства | 28 зарегистрированных действий; параметры, результат в переменную, защита результата | Python Registry + Pydantic; поиск/группировка большой библиотеки — этап 3 |
| Несколько одновременно открытых проектов | Один редактируемый граф и список сохранённых проектов | Вкладки нескольких документов — этап 3 |
| Масштабирование, сохранение | Fit, 100%, прокрутка; JSON хранит координаты, связи, breakpoint | v1 → v2 мигрируется при загрузке; исходный v1 сохраняется до явного Save |
| Встроенный браузер | В продукте пока отдельное окно Chrome/Chromium/Edge | Реальный Qt/CDP-прототип; производственный провайдер и GUI-хост — этап 3 |
| Начать/остановить запись | Есть, независимо от CMS и определения формы | DOM-канал прежнего Recorder; сетевые тела/пароли POST не захватываются |
| Продолжение записи | После выбранного кубика, с сохранением его прежнего Success-продолжения и Error-связи | Сохраняется браузер остановленной записи; вставленные действия не удаляют существующие |
| Авторизация и iframe | Обычный POST/CSRF, парольные ссылки, iframe-путь | Тестируется контролируемая форма входа в iframe; произвольный SSO не заявляется |
| Навигация и отсутствие дублей | ID события, объединение ввода, привязка ожидания к действию, SPA/history/fragment | WaitURL использует реальные события и историю; неизвестный результат не повторяет форму |
| Выбор элемента и атрибуты | Есть: указатель на странице, CSS, XPath, iframe и атрибуты с маскированием | Inspector повторно использует генератор селекторов; полный DOM-tree — этап 3 |
| Проверка селектора | Подсветка совпадений и их количество; ручное исправление кубика | CSS / `xpath=…`; автоматическое восстановление после изменения сайта — этап 3 |
| Извлечение данных | Browser.ReadText / ReadAttribute → переменная | Общий результат действия; массовый парсинг/таблицы — этап 3 |
| Переменные и входы | JSON-типы, Set/Get/Delete/Increment/Compare, входы, подстановка `{{name}}` | Изолированный Variables на каждое выполнение; нет Python eval |
| Строки | concat/replace/lower/upper/strip/split/join/length/substring | Strings.Transform; остальные операции добавляются через Registry |
| Списки | JSON-списки, split/join, For Each, индекс и текущий элемент | Отдельные CRUD-кубики, привязка к файлу — этап 3 |
| Таблицы и файлы данных | Нет специализированного редактора и файловых экшенов | Не подменяются CSV-генератором Poster 2.0; этап 3 |
| IF / ELSE | Logic.If для DOM/URL и Variables.Compare для значений | False идёт по Error без статуса ошибки; исключение тоже имеет отдельный статус |
| SWITCH | Значения → видимые выходы C1…C20; Success — default, Error — исключение | Дополнительные типизированные порты в графе v2 |
| Циклы | N раз и For Each, лимит итераций, Break/Continue ближайшего цикла | Стек циклов в Context и общий max_steps; визуальные группы — этап 3 |
| Паузы и завершение | Delay, End.Success, End.Failure; прежний End сохранён | Error-ветви и единые коды ошибок; бесконечный проход ограничен |
| Группы, подпроекты | Пока нет | Стабильные ID/версии, расширения формата; этап 3 |
| Breakpoint, Step, Continue | Есть, с настоящим сохранением Context и указателя | GraphRunner не пересоздаёт браузер при продолжении |
| Правка при паузе | Совместимые параметры, результат, breakpoint и значения переменных | Топология, тип действия и параметры циклов при паузе защищены от изменения |
| Выполнение выбранного действия | Есть в текущей сессии; указатель графа сохраняется | Явное подтверждение; Step используют, когда нужно продвинуть указатель |
| Журнал и диагностика | Статусы, длительность, код, маска/адрес ожидания, значения переменных | Секреты маскируются; полноценный Trace Viewer как продуктовая функция — этап 3 |
| Вкладки браузера | NewTab/SwitchTab/CloseTab и базовые кнопки конструктора | Запись пока одной активной вкладки; popup/multitab recorder — этап 3 |
| Cookies / сессии / профили | Живая изолированная сессия Maker; encrypted session прежнего HTTP Recorder | Редактор профилей и явный импорт/экспорт cookies Maker — этап 3 |
| HTTP-операции | Прежний HTTP Engine, Workflow v1, SQLite, Drive и KB сохранены | HTTP-кубики для нового графа — этап 3; не смешаны с браузерными действиями |
| Python / пользовательский код | Исполнитель на Python, Registry расширяется доверенным кодом | Произвольный Python из импортированного JSON не выполняется; кубики кода — отдельный будущий контракт |
| Повторения и потоки | Один Maker run, данные изолированы; прежняя очередь HTTP работает | Новый диспетчер GraphRunner, квоты, повторы и приоритеты — этап 4 |
| Windows / Linux / VPS | Portable GUI Windows и отдельный Python CLI без GUI | Системный браузер нужен для Browser-кубиков; HTTP Engine остаётся без браузера |
| Molab / Colab | Возможен тот же Python runtime, без зависимости от Tk/Qt | Новое развёртывание и диспетчер не реализуются на этапе 2; отдельный следующий этап |
| Импорт проектов ZennoLab | Нет | Функциональная совместимость сценариев не означает совместимость закрытого формата |

Порядок следующих работ: производственный browser-provider с явным согласием на крупные компоненты → редактор данных/подпроекты/HTTP-кубики → диспетчер выполнений и облачные окружения. Полный аналог ProjectMaker + ZennoPoster остаётся целью продукта, а не заявленным результатом этапа 2.
