# Poster 3.0, этап 1 — визуальный ProjectMaker

Разработка начинается от проверенного `b2baca8844978c5755a136fa08a0db3ac4ca688d` в отдельной ветке `codex/poster-3-projectmaker-stage1`. Старая ветка Poster 2.0 и PR №2 не меняются; merge в main не выполняется.

## Работа без терминала

Распакуйте portable Windows ZIP целиком и откройте **Poster.exe**. ProjectMaker открывается первым. Python устанавливать не нужно. Нужен существующий Chrome/Chromium/Edge; выбор браузера и согласованная загрузка доступны во вкладке «Система». Дополнительный браузер автоматически не скачивается.

1. Нажмите **«Демо-сайт»**, затем **«Начать запись»**. Для другого сайта введите его URL и начните запись.
2. В открывшемся окне Chrome нажмите «Показать форму», заполните поле, выберите значение списка, нажмите «Перейти дальше».
3. Вернитесь в Maker и нажмите **«Остановить запись»**. Действия появляются отдельными соединёнными кубиками; перед взаимодействиями добавляются явные ожидания элементов.
4. **«Показать всё»** подбирает масштаб; «100%» возвращает обычный. Выберите Browser.Input, измените «Текст», нажмите **«Применить»**.
5. **«Шаг»** исполняет один кубик. **«Запустить»** начинает/продолжает граф. Текущий кубик подсвечен, результаты и ошибки видны в журнале. «Остановить» прерывает дальнейшие действия и закрывает браузер. Уже совершённые операции на сайте не отменяются.
6. **«Сохранить»** пишет проект в `.poster/maker-projects`; «Сохранить как…» позволяет выбрать файл. При следующем запуске последний сохранённый граф открывается автоматически. Запуск остаётся явным действием пользователя.
7. Для собственного демо-сайта сохраняется его loopback-порт. При воспроизведении сохранённого демо Maker сам поднимает сервер на том же порту. Занятый чужим процессом порт вызывает понятную ошибку и не используется как наш сайт.

Для реального сайта все обычные запросы браузера, в том числе POST-авторизация, разрешены. Это самостоятельный режим пользовательской записи, не RecognitionSession с ограничением одной публикации. CAPTCHA, SSO и динамические одноразовые коды не обходятся.

## Редактирование настоящего графа

Двойной щелчок по действию в библиотеке или «Добавить кубик» создаёт узел вручную. Перетаскивание меняет координаты. Shift+клик выделяет несколько кубиков. «Копировать кубик» дублирует выделение; Ctrl+C/Ctrl+V работают на холсте. Delete/«Удалить» удаляет кубик или выбранную стрелку. «Отменить правку»/Ctrl+Z возвращает предыдущий снимок.

Нажмите зелёный порт **S (Success)** или красный **E (Error)**, затем вход/тело следующего узла. Новый выход заменяет предыдущую связь того же порта. Входящих стрелок может быть несколько. Ошибки действия идут по Error; без такой связи выполнение останавливается. У Logic.If истинное условие идёт по Success, ложное по Error; ложное условие не считается исключением. End завершает путь. Порядок узлов в JSON и координаты не определяют исполнение — только стрелки и точка входа.

Редактирование действия во время записи/активной пошаговой сессии запрещено; сначала остановите её. Несоединённые кубики не исполняются. Стартом служит entry-узел Start. Если он удалён, добавьте новый Start.

## Первые действия

| Тип | Параметры и поведение |
|---|---|
| Start / End | Начало и завершение пути |
| Browser.OpenURL | HTTP(S) URL или ссылка на секрет |
| Browser.Click | Селектор, iframe-путь, кнопка мыши, timeout |
| Browser.Input | Селектор, текст/secret_ref, iframe, timeout; пароль требует секрет |
| Browser.Select | Нативный select, список значений |
| Browser.WaitElement | visible/attached/hidden/detached и timeout |
| Browser.WaitURL | URL-маска и timeout; синхронизация перехода без повторного запроса |
| Logic.If | exists/not_exists/text_contains/url_contains/equals |

Новые действия регистрируются через `Registry.register(Action(...))`: отдельная модель параметров, async-исполнитель, поля свойств и версия действия. JSON не импортирует Python-модули и не выполняет выражения через eval.

## Формат и совместимость

`format: "poster.maker.graph"`, `schema_version: 1`. Это отдельное пространство форматов, а не замена `Workflow v1`. Узлы имеют стабильные ID, type/action_version, параметры, title, x/y и extensions. Связь — source/port/target. Проект содержит entry, масштаб, max_steps, metadata/extensions и ссылки на зашифрованный bundle. [Схема](../schemas/maker-graph-v1.schema.json), [каталог параметров](../schemas/maker-actions-v1.json), [пример ветвления](../examples/maker/branching.postergraph.json).

Версия действия отделена от версии контейнера. Новые HTTP/Python/подпроектные действия могут добавляться через registry без изменения Workflow v1. Metadata/extensions оставляют место требованиям окружения, переменным, спискам и облачному диспетчеру. Переходы могут образовывать циклы, но лимит max_steps останавливает обход; отдельного Loop-кубика пока нет.

HTTP Runtime/Engine, SQLite schema, Drive, KnowledgeBase, старые проекты и распознающий Recorder остаются прежними. Старые разделы находятся в соседних вкладках; `poster recorder` по-прежнему открывает старый раздел. Распознающий режим сохраняет свои защитные ограничения, универсальная запись их не наследует.

## Секреты

Парольные поля и известные признаки protected-input обнаруживаются до построения узла. В граф передаётся `{"secret_ref":"..."}`, а значение сразу шифруется существующим Fernet/key-сервисом. В новом режиме не захватываются тела запросов, cookies, HAR или исходный Codegen-файл. Журнал содержит тип действия, результат, код ошибки и короткие безопасные значения результата, а не вводимые тексты/пароли.

Зашифрованные `*.secrets.enc` сохраняются рядом с графом. Граф ссылается на неизменяемый bundle с SHA256; graph JSON заменяется атомарно последним. Ключ хранится отдельно в `.poster/private`. При переносе на другой компьютер защищённые значения можно задать заново. Для ручного ввода пароля включите «Защищённое значение» до применения. Непомеченный обычный текст сохраняется как текст; Maker не может угадать назначение произвольной строки вне браузера.

Ссылки `env:NAME` в headless-режиме требуют явного `--secret-env NAME`. Проект не получает доступ ко всем переменным окружения автоматически. Старые ключи и legacy fallback сохраняются.

## Codegen и запись

Изучен установленный `playwright codegen --help` и канал recorder в поставке Playwright. Публичный CLI выдаёт программы Python/JS и других языков, не стабильный графовый поток с нашим контрактом секретов. Разбор сгенерированного исходника или private recorder API не стал основой первого этапа. Переиспользован существующий `Recorder.attach_actions`: expose_binding + add_init_script, отдельно от HTTP-захвата.

События доверенного пользовательского ввода преобразуются в кубики; последовательный ввод одного поля объединяется. Селекторы предпочитают ID/test-id/name/aria-label, затем структурный путь. Для навигации используются события Chromium/CDP и document identity: ввод URL даёт OpenURL, переход от клика — WaitURL. WaitURL не повторяет POST/GET, а ждёт браузер. Нестабильные числовые/длинные сегменты URL превращаются в маску; это синхронизация, не подтверждение бизнес-результата.

## Настоящий браузер и следующий этап встраивания

**Chromium не встроен в холст/окно Maker.** Это отдельное управляемое окно; об этом прямо написано в интерфейсе. Встраивание внешнего Chrome через SetParent было бы хрупким: отдельные процессы/окна, ввод и DPI, popup и жизненный цикл, отсутствие переносимости.

Требование встроенного браузера сохраняется на **этап 2**. Предпочтительный кандидат — Qt/PySide6 + QWebEngineView с отдельным адаптером и проверенным CDP/QWebChannel-контрактом. Перед переходом нужны прототип совместимости Playwright, изолированный профиль, защита локального управляющего канала, iframe/SSO/popup/download, DPI/фокус и Linux-провайдер без GUI. CEF — альтернативный вариант после оценки актуального Chromium и поддержки Python 3.12. Эти крупные зависимости в пакет этапа 1 не добавлены.

## Проверки и ограничения

`check_maker.py` реально записывает browser input/click/select/navigation, меняет параметр, перемешивает порядок узлов, воспроизводит по стрелкам, сохраняет/загружает координаты и повторяет выполнение. Отдельный вход проходит настоящий POST + CSRF с фиктивным паролем; JSON, encrypted bundle и trace проверяются на отсутствие plaintext.

`test_maker.py` проверяет оба выхода If, Error-ветку, прерывание ожидания, лимит циклов, расширяемую регистрацию, секреты, несовместимые версии, сохранность старого файла, настоящий Tk-холст и CLI в процессе, запрещающем импорт tkinter. Windows CI дополнительно управляет portable exe и Chrome через OS mouse/keyboard, редактирует кубик и повторяет сохранённый граф после перезапуска. Результаты конкретного коммита и SHA256 публикуются только после CI.

Этап 1: одна записываемая вкладка; нет полноценного popup/multitab, file upload/download, drag-and-drop, горячих клавиш как отдельных действий, закрытого Shadow DOM и гарантированного восстановления CSS-селекторов при изменении сайта. Некоторые iframe поддержаны селекторным путём, но произвольные cross-origin/SSO-сценарии не заявляются. Необычные действия нужно добавить/исправить вручную. Нормальные ссылки, адресная навигация, текстовые поля, нативный select и вход формой покрыты. Нет Molab, нового планировщика, облачного диспетчера и сотен кубиков. Сборка для испытаний не подписана коммерческим сертификатом.
