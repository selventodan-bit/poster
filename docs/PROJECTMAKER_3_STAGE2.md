## Первая проверка без терминала

Распакуйте portable ZIP целиком, запустите `Poster.exe`. Нужен установленный Chrome/Chromium/Edge; автоматической загрузки браузера или Qt нет.

1. **«Демо-сайт» → «Пример с циклом»** создаёт нетривиальный проект с For Each, строками, переменными, чтением результата, Compare, Break/Continue и Switch.
2. Выберите Browser.Input, включите **«Точка останова»**. Нажмите «Запустить», задайте вход `prefix` и подтвердите выполнение.
3. На паузе выберите Input и измените текст, например на `Исправлено: {{note}}`; нажмите «Применить». Браузер и указатель сохраняются.
4. Во вкладке справа **«Переменные»** видны начальные и текущие значения. «Задать» меняет определение проекта; «Задать в отладке» меняет только текущее выполнение. Пароли/токены помечаются как защищённые.
5. **«Выполнить кубик»** проверяет выбранное действие в текущем браузере, с отдельным подтверждением. Оно не продвигает указатель: для этого служит «Шаг». Чтобы выполнить остаток примера сразу, снимите breakpoint и нажмите «Запустить».
6. Пример делает две публикации на собственном сервере, читает текст в `last_text`, завершает цикл через Break и выбирает успешный выход Switch. `counter` равен 2.
7. Сохраните проект, закройте приложение и откройте снова. Последний граф загружается, демо-сервер поднимается при явном запуске, входы задаются заново. Данные прошлого run не переносятся в новый.

## Запись и конструктор действий

Обычная запись: URL → «Начать запись» → действия в браузере → «Остановить запись». Остановленная запись сохраняет браузер до следующего запуска/остановки/закрытия приложения. Выберите кубик и нажмите **«Продолжить запись»**: новые действия вставляются после него в зелёный путь; прежнее продолжение и красная ветка остаются. Для возврата на страницу используйте адрес браузера или URL/«Открыть URL» Maker. Продолжение не требует сохранения/отбрасывания текущего графа.

Во вкладке **«Элемент»** можно открыть браузер по URL, нажать «Выбрать на странице» и кликнуть элемент. Этот клик перехватывается, не отправляя форму. Escape отменяет выбор. Видны атрибуты, CSS/XPath и iframe-путь. «Проверить» показывает число совпадений и подсвечивает их. «В кубик» переносит селектор в выбранное действие. «Читать текст» / «Атрибут» создают действие с сохранением в названную переменную; его нужно соединить в графе. Здесь же доступны базовые кнопки вкладок; эквивалентные действия есть в библиотеке.

Парольные события сразу превращаются в `secret_ref`. Universal Recorder не использует RecognitionSession/POST gate и не сохраняет тела запросов, cookies или HAR. ID события предотвращает повторную обработку; последовательный ввод объединяется. Iframe записывается селекторным путём. Навигация от действий, History API и hash-ссылок отделяется от явного открытия адреса.

## Переменные и действия

Имя: `[A-Za-z_][A-Za-z0-9_]{0,79}`. Значения — JSON-типы; ввод поля GUI принимает текст или JSON, например `12`, `true`, `["one","two"]`. `{{name}}` целиком сохраняет тип значения, внутри строки делает подстановку. В JSON параметров допустима ссылка `{"variable":"name"}`. Выражения, функции и Python `eval` не поддерживаются.

В свойствах каждого действия есть **«Результат → переменная»** и **«Поле результата»**: `value` для ReadText/Get/String, `index` для NewTab; пустой путь сохраняет весь объект. Точки в пути выбирают вложенное поле/индекс списка. «Защитить результат» шифрует сохранённое значение и скрывает вывод журнала. Защита распространяется через подстановки и строковые операции. Значения независимых запусков копируются, не сохраняются как новые defaults.

Дополнения к библиотеке этапа 1:

| Действия | Поведение |
|---|---|
| Variables.Set/Get/Delete/Increment | Чтение/изменение переменной, прибавление числа |
| Variables.Compare | equals/not_equals/lt/le/gt/ge/contains/starts_with/ends_with; True → S, False → E |
| Strings.Transform | concat/replace/lower/upper/strip/split/join/length/substring |
| Logic.Switch | Фиксированный список вариантов; C1…C20, S = default, E = исключение |
| Logic.Loop | N итераций; S = тело, E = выход; из тела связь обратно на Loop |
| Logic.ForEach | Снимок списка, переменные элемента и индекса с нуля; те же S/E |
| Logic.Break / Continue | Ближайший активный цикл: выход через его E / возврат к его заголовку |
| Logic.Delay | Ожидание 0…120000 мс, прерывается остановкой |
| End.Success / End.Failure | Явное успешное/неуспешное завершение; прежний End сохранён |
| Browser.ReadText / ReadAttribute | Результат в поле value; парольные/токенные атрибуты защищаются |
| Browser.NewTab/SwitchTab/CloseTab | Создать, выбрать индекс с нуля, закрыть текущую |

S/E у условий и заголовков циклов — переходы логики, а не автоматическое признание False/завершённого цикла ошибкой. У исключения статус FAILED и код ошибки. Break/Continue имеют явную семантику ближайшего цикла, поэтому их продолжение определяется активным стеком. Глобальный `max_steps` (по умолчанию 500, максимум 10000) и `max_iterations` защищают от бесконечного обхода. Визуальные группы/подпроекты остаются будущей работой.

## WaitURL и отладка

Записанный WaitURL хранит `after_node`: ID действия, вызвавшего переход. Runtime помнит события навигации по страницам и checkpoints действий. Поэтому OpenURL → Click → Input → WaitURL может подтвердить переход от Click, даже если последующий Input уже выполнялся на новом документе. Ожидание не повторяет GET/POST.

Проверены отдельные причины ошибок: перехода после действия не было, адрес не совпал с маской, не завершилась начальная загрузка. В GUI-журнале есть причина, фактический URL, ожидаемая маска, timeout и последние адреса. Чувствительные query-значения и длинные токены маскируются. Маски поддерживают `*` внутри сегмента и `**` через разделители; остальные символы буквальные. Это синхронизация, не проверка бизнес-успеха.

Для v1 без after_node остаётся консервативное ожидание после последнего действия. Если после навигации вручную вставлен Input, укажите/перезапишите ожидание для вызывающего переход кубика; новый Recorder сохраняет эту связь автоматически. Неудача после отправки формы не приводит к автоматическому повтору.

Breakpoint действительно останавливает Python GraphRunner до действия. Продолжение использует те же Context, переменные, стек циклов и browser session. При паузе разрешены совместимые параметры обычного действия, вывод результата и breakpoint. Изменение топологии/типа/версии действия и параметров циклов/Switch требует остановки. Необработанная ошибка завершает run; исправление и новый запуск требуют явного решения пользователя. Автоматического повторения неясной публикации нет.

## Формат, запуск Linux и совместимость

Контейнер по-прежнему `poster.maker.graph`, теперь `schema_version: 2`: variables, breakpoint/save_as/result_path/protect_result и case-порты. [Схема v2](../schemas/maker-graph-v2.schema.json); схема v1 не переписана. Загрузка v1 мигрирует в памяти. При явном сохранении поверх v1 создаётся исходный `*.v1.bak`. Старый Workflow v1 и READY-проекты читаются прежними компонентами; SQL schema, HTTP Runtime/Engine, Drive и KnowledgeBase не переписаны.

```bash
python -m poster maker-run my-project.postergraph.json --input prefix=Linux --output run-report.json
python scripts/check_maker_stage2.py --output .poster/my-stage2-check
```

Batch CLI игнорирует breakpoint по умолчанию; `--breakpoints` возвращает PAUSED для управления через отдельный клиент. Защищённые входы задаются ссылками, например default `{"secret_ref":"env:MY_TOKEN"}` плюс явный `--secret-env MY_TOKEN`. Открытые секреты через `--input` CLI не принимаются. GUI запрашивает их маскированным диалогом. Для браузерных действий Linux нужны Playwright и браузер; Tk/Qt не импортируются. Источники данных и секреты не включены в ZIP.
