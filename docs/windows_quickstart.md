# Windows: запуск Recorder

Нужны Windows 10/11 x64 и 64-разрядный Python 3.11, 3.12 или 3.13 с python.org, включая pip и Tcl/Tk. Для первого запуска нужен интернет. Проверенный ZIP и SHA256 см. в отчёте существующего PR №2; Git и Docker для Recorder не нужны.

1. Распакуйте Windows artifact в доступную для записи папку и дважды щёлкните **start_recorder.cmd**. При первом запуске необходимые зависимости и Chromium устанавливаются автоматически.
2. В Recorder вставьте URL, заголовок и текст. Для ответа/комментария выберите reply/comment; заголовок не требуется. Выберите папку для готового проекта. Нажмите **«Распознать сайт»**.
3. Проверьте подсвеченные поля. Если нужен вход, откройте страницу входа в браузере, нажмите **«Разрешить один вход»**, войдите и повторите распознавание нужного раздела. Авторизация остаётся в личном профиле проекта.
4. **«Тестовая публикация»** разрешает одну настоящую запись. **«Проверить HTTP»** отдельно разрешает вторую запись с новой пометкой в заголовке и тексте.
5. После успешной HTTP-проверки проект автоматически сохраняется в выбранную папку. Его также можно сохранить кнопкой **«Сохранить проект»**. Заполненные папки не перезаписываются.

CSS, cookies, YAML и служебные маркеры вводить не нужно. Ctrl+C/V/X/A, русская раскладка и контекстное меню сохранены. Ключи вне папки проекта; прежний `%USERPROFILE%\.poster\session.key` используется без перезаписи. Не удаляйте ни старый, ни новый ключ.

Если есть несколько равнозначных форм, выбор находится в расширенных настройках. «Обучить вручную» позволяет показать одну публикацию обычным текстом; найденные поля заполняются автоматически. После неё нажмите «Завершить обучение». Для входа используется отдельное разрешение. `UNKNOWN` означает, что запись могла состояться: повтор в этой сессии заблокирован.

Для первой локальной проверки, без записей на внешнем форуме:

```powershell
.\.venv\Scripts\python.exe -m poster fixtures-v2
```

Оставьте сервер запущенным, откройте Recorder и используйте `http://127.0.0.1:8765/recognize/ajax`. Более широкий автоматический набор:

```powershell
.\.venv\Scripts\python.exe -m poster benchmark-recognition --output .poster\benchmark-windows
```

Отчёт появится в `.poster\benchmark-windows\report.json`. Полный сервисный Browser → HTTP → экспорт → новый процесс Runtime проверяется Windows CI на Python 3.11/3.12/3.13 из распакованного пакета. Настоящая Tk-инициализация и буфер проверяются отдельно; это не полный GUI E2E. Итог конкретного пакета и ограничения: [USER_READINESS.md](USER_READINESS.md).

Если Windows сообщает об отсутствии Python, установите одну из указанных версий с pip и Tcl/Tk. Launcher восстанавливает зависимости и проверяет реальный запуск Chromium; несовместимый venv сохраняет в `.venv-backup-*`. Отсутствие доступа к папке или сети требует устранения указанной причины, а не правки Python-файлов. Перед обновлением закройте Recorder, сохраните `.poster` и ключи; исходники можно заменить поверх.

Дополнительные CDN задаются в расширенных настройках точными HTTPS origin без путей, например `https://static.example.org`. Для них запрещены query-параметры и частные DNS-адреса; cookies и Authorization не передаются. Заблокированный ресурс отмечается отдельной диагностикой.
