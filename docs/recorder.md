# Recorder

Запуск `python -m poster recorder`, опциональная зависимость `.[recorder]`, Playwright Chromium и tkinter. В headless cloud UI не требуется: `poster demo` использует тот же capture/analyze/export путь с автоматическими действиями на fixture.

1. «Новый проект»: ID из латинских букв/цифр, `_`/`-`. Укажите URL формы. Fixture URL: `http://127.0.0.1:8765/classic/new` и `/csrf/new`.
2. «Запись» открывает отдельный профиль `.poster/profiles/<id>`. Не используйте обычный профиль пользователя. На реальном сайте можно вручную авторизоваться в этом профиле.
3. UI показывает уникальные маркеры. Вставьте title и body в соответствующие поля; нажмите отправку. Дождитесь подтверждённой страницы.
4. «Стоп» завершает сбор и закрывает Chromium. «Анализ» ищет write с обоими маркерами, DOM формы и GET-источник hidden-полей.
5. Укажите CSS подтверждения. Он должен отличать успех от возвращённой страницы формы с ошибкой. Для fixtures `[data-result-id]` автоматически дополняется проверками title/body. HTTP-код не заменяет эту проверку.
6. «Проверить HTTP» после явного согласия выполняет отдельную настоящую отправку. Факт HTTP_READY ещё не доказывает переносимость авторизации.
7. «Экспорт»: пустая папка `<id>`. READY записывается последним; перенесите все файлы в каталог Engine/Drive. Ключ не переносите в проект.

Повторная «Запись» в той же UI-сессии сравнивается с предыдущей: изменения полей с невыясненным происхождением переводят проект в REVIEW. «Открыть» загружает опубликованный проект для переобучения, сохраняя кампанию, лимиты и другие настройки; экспортируйте новую версию в отдельную пустую папку, затем обновите действующую папку с READY последним. Не затирайте базу Engine.

Статусы: HTTP_READY (ограниченный анализ успешен), REVIEW (нужна проверка источника/формата/confirmation), BROWSER_REQUIRED (не найдена однозначная операция с маркерами). Автоматический browser fallback не реализован. REVIEW-проект можно экспортировать для анализа, но Registry не выполняет его; неполная DSL не пройдёт validate.

Сырые запросы, ответы, DOM и действия не выгружаются автоматически. Только cookies и поддержанные Authorization/X-API-Key/X-Auth-Token сохраняются в encrypted session. localStorage в storage_state сохраняется зашифрованно для диагностики, но HTTP Engine его не выполняет и не превращает автоматически в заголовки. Если авторизация зависит от JS, нужен ручной DSL или REVIEW.

Ключ:

```bash
# Linux/macOS — секрет не выводится на экран:
export POSTER_SESSION_KEY="$(python -m poster keygen)"
```

```powershell
# Windows PowerShell:
$env:POSTER_SESSION_KEY = python -m poster keygen
```

Сохраните ключ через свой секретный менеджер: потеря ключа требует повторной записи сессии. Демо хранит временный ключ в `<output>/private/session.key` отдельно от `<output>/projects`; не загружайте всю output-папку на Drive.
