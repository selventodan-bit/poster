# Recorder 2.0

Основной путь: URL, заголовок и текст → **Распознать сайт** → предпросмотр и подсветка полей → **Тестовая публикация** → **Проверить HTTP** → **Сохранить проект**. Копировать служебные маркеры и указывать CSS не требуется. Windows: `start_recorder.cmd`. Другие desktop-системы: `python -m poster recorder`.

Распознавание открывает выделенный Chromium-профиль `.poster/profiles/<id>`; браузерный gate запрещает POST/PUT/PATCH/DELETE и сторонние домены. Узнаваемая кнопка создания темы может быть нажата для показа формы. Отправка происходит только после отдельного подтверждения в UI. Не включайте режим обучения ради простого исследования.

После первой отправки Recorder проверяет постоянную ссылку независимым HTTP GET и сверяет заголовок/текст. JSON/AJAX-ответы, текстовый multipart, contenteditable и same-origin iframe входят в проверенные fixture-сценарии. При неизвестном источнике параметров или отсутствии подтверждения появится конкретная диагностика. HTTP 200 не считается успехом.

## Отдельная HTTP-проверка

`HTTP_CANDIDATE` означает подготовленный сценарий. Кнопка «Проверить HTTP» требует разрешение на **вторую настоящую публикацию**. Можно перед этим изменить заголовок/текст в UI: это проверяет повторяемость переменных. Только успешная семантическая проверка даёт `HTTP_VERIFIED`; новый исполняемый проект имеет `status: HTTP_READY` и метаданные evidence. При UNKNOWN повтор текущей попытки запрещён.

«Сохранить проект» создаёт `<выбранный каталог>/<id>/`. Существующие файлы не перезаписываются. Можно явно сохранить непроверенный кандидат, но он останется REVIEW и не будет исполняться Engine. Для переноса в Drive загружайте только папку проекта, READY последним. `recognition.json` содержит безопасные оценки, коды причин и историю состояний.

## Ручное обучение и переобучение

Если автоматика не справилась, нажмите «Обучить вручную» и подтвердите ручной вход/одну отправку. Найденные поля заполнятся обычным текстом из UI; при необходимости покажите правильную форму и вставьте исходный текст самостоятельно. После отправки и появления результата нажмите «Завершить обучение». Анализ использует те же DOM/HTTP данные; запись без достаточного подтверждения не становится рабочим проектом.

В расширенном режиме можно выбрать одну из нескольких форм, посмотреть структурированную диагностику, изменить ID и открыть старый проект для переобучения. Настройки кампании/лимитов сохраняются в новом Build; новая версия экспортируется отдельно. Для неизвестного DOM автоматически сформировать обобщаемое правило удаётся не всегда; подтверждённый HTTP-кандидат и знание формы — разные результаты.

## Сессии, настройки и остановка

Cookies и поддерживаемые auth-заголовки сохраняются только в session.enc с Fernet. При наличии POSTER_SESSION_KEY используется он. Иначе desktop Recorder создаёт `.poster/private/session.key` с ограниченным доступом; это не часть проекта/Drive. Потеря ключа требует новой записи сессии. На VPS задайте тот же ключ безопасным способом. Browser profiles также содержат приватное состояние и не должны выгружаться вместе с исходниками.

В `.poster/knowledge.sqlite` хранятся только роли, тип редактора, структурная позиция, версия, результаты проверок и счётчики. URL, сообщения, cookies, пароли и значения токенов туда не попадают. Правило другого сайта помогает выбрать кандидата, но не доказывает HTTP-совместимость.

Последние URL и ID сохраняются в `.poster/recorder-settings.json`; credentials/query/fragment из URL удаляются, текст сообщения не сохраняется. Clipboard-обработка из main перенесена без изменения поведения: Ctrl+C/V/X/A, русская раскладка и меню правой кнопки.

«Стоп» отменяет операцию и закрывает браузер. Результаты старых запусков отсеиваются по generation ID и не меняют новое окно состояния. После неожиданной ошибки можно начать новое распознавание. Перед повторным явным тестом после UNKNOWN проверьте сайт вручную, чтобы не создать дубль.

## Команды разработчика

```bash
python -m poster fixtures-v2 --port 8765
python -m poster recognize http://127.0.0.1:8765/recognize/ajax
python -m poster demo-recognition --output .poster/check-v2
```

Legacy `Recorder`, `builder.analyze` и прежний `poster demo` сохранены для совместимости и регрессии. Новый UI использует NetworkAnalyzer/HTTPWorkflowLearner поверх общего Capture и Build/export. Детали и ограничения — [recognition_architecture.md](recognition_architecture.md).

## Глубокая доработка

Актуальные ограничения навигации, редакторные адаптеры, шесть категорий знаний, точная изоляция origin, отдельный login и безопасное использование прежних ключей описаны в [архитектуре](recognition_architecture.md). Перед HTTP-тестом GUI создаёт другой контент. При заранее выбранной папке подтверждённый проект сохраняется автоматически. Полный автоматический набор и реальная установка phpBB: [отчёт](VALIDATION_V2_DEEP.md). Порядок действий Windows: [краткая инструкция](windows_quickstart.md).
