# Poster 2.1 recognition: устройство и границы

Доработка существующего PR №2; YAML schema v1, Engine, READY, Drive, SQLite и генератор сохранены. Аудит исходной версии: [RECOGNITION_AUDIT.md](RECOGNITION_AUDIT.md). Результаты испытаний: [VALIDATION_V2_DEEP.md](VALIDATION_V2_DEEP.md).

## Поиск и заполнение

`EngineDetector` разделяет платформу и форумный компонент: WordPress и wpForo могут обнаруживаться одновременно. Версионированный реестр адаптеров анализирует независимые каналы generator, DOM, assets, routes, API, runtime behavior и response headers. Повторение одной сигнатуры не добавляет доказательств. Требуются минимум два канала; версия берётся из generator, если он её сообщает. Оценки эвристические, не вероятности. Наличие идентификации не означает поддержки публикации. Для phpBB отдельно указана проверенная контролируемая конфигурация 3.3.15/prosilver; остальные семейства пока имеют уровень identification.

`NavigationDiscovery` рассматривает accessible name (ARIA/label/title/SVG title), роли, тип, URL, окружение navigation, управляемую область и наличие редактора/меню в этой области. Не опирается на одно название кнопки. Поддерживает последовательность до пяти переходов, ссылки, меню, иконки, вкладки, открытие формы и доступные этапы формы. Одинаковые ссылки на один URL считаются одним назначением. Равнозначные разные назначения требуют выбора. Submit, опасные маршруты и не классифицированные действия не используются для исследования. Связанный через ARIA локальный этап внутри формы может открываться кнопкой type=button; предыдущий заголовок сохраняет своё сопоставление. Шаги, требующие отправки данных до показа следующей страницы, автоматически не проходятся.

Словари находятся в `poster/recognition/data/locales.json`. `Localizations(extra=Path(...))` добавляет проверяемый JSON без изменения алгоритма. Это вспомогательные признаки, наряду со структурой и отношениями контролов. Полное accessibility API дерево не запрашивается: анализируются его доступные DOM-признаки.

`UniversalFormDetector` обходит обычный и открытый Shadow DOM, HTML/ARIA/JS формы, модальные области и разрешённые iframe. Сохраняет альтернативы полей с оценками и объяснениями; учитывает тип, accessible label, контекст и расположение относительно редактора. Исключает login/search/profile/contact и не угадывает равные варианты. Временные DOM-метки очищаются при повторном анализе, чтобы скрытый старый элемент не получил селектор нового.

`EditorAdapter` использует доступные публичные API TinyMCE, CKEditor, Quill, ProseMirror, Summernote и Froala; иначе применяет native input и события input/change/blur. Поддержаны iframe и contenteditable. Readback подтверждает только заполнение. Реальная синхронизация редактора доказывается содержимым захваченного запроса и независимым чтением публикации. Тесты API-совместимых редакторов не означают проверки всех оригинальных версий этих библиотек.

## Знания

SQLite `user_version=2` мигрирует прежние правила с сохранением ID/счётчиков. Закрытая Pydantic-модель содержит шесть категорий:

| Категория | Обобщённое содержимое |
|---|---|
| EngineKnowledge | Семейство, возможная числовая версия, версия адаптера, каналы доказательств |
| NavigationKnowledge | Назначение, структурные признаки и последовательность безопасных переходов |
| FormKnowledge | Тип редактора, связи поля заголовка с редактором, число полей, light/shadow/dialog layout |
| SubmissionKnowledge | Методы, кодировки, вложенная форма данных, роли контента, формы маршрутов и граф зависимостей |
| TokenKnowledge | Безопасные известные имена/обобщённые роли и свежие HTML/JSON/header/cookie источники |
| VerificationKnowledge | JSON/bookmark/redirect permalink, обязательные роли title/body, независимый GET |

Нет CSS-селекторов, адресов сайтов, текстов, паролей, cookies или значений токенов. Неизвестные имена параметров нормализуются в `other`; сегменты нестандартных маршрутов — в структурные категории. Свидетельства установок — HMAC-идентификаторы с локальной солью, исключённые из экспорта.

Правила имеют приоритет, ревизии/историю, enabled, положительные и отрицательные свидетельства. Несовместимый редактор/семейство отсекается; точное/совместимое сопоставление получает объяснимый рейтинг. Связь before/after-editor предпочтительнее позиции. При равных противоречащих правилах поле не выбирается. Позиционная гипотеза остаётся менее надёжным fallback; она не переносит доказательство публикации. Неудачные правила исключаются после установленного порога, их можно отключить. Новая структурная разновидность получает отдельное правило и не перезаписывает старую.

Знания улучшают сопоставление полей, ранжирование уже признанных безопасными переходов и приоритет поиска локальных источников параметров. Сетевая структура хранится как наблюдённый образец, но не исполняется на другом сайте без записи его реального обмена. Совпадение схемы запросов не разрешает создавать HTTP-проект из памяти.

Зрелость: observed → single-site → independent-variants → independent-installations → regression-tested. Последние два уровня требуют HTTP-свидетельств на разных установках известного семейства; одного счётчика успехов недостаточно. Уверенность формы и HTTP_READY независимы. Импортированные правила теряют чужие счётчики и доказательства. Есть безопасный экспорт/импорт, дедупликация, backup SQLite с integrity_check; backup восстанавливают в новый файл.

```bash
poster knowledge list
poster knowledge export --file rules.json
poster knowledge import --file rules.json
poster knowledge disable --rule form-0123456789abcdef
poster knowledge backup --file knowledge-backup.sqlite
```

## Сеть и исполнение

Capture связывает ответ с исходным request ID/action, redirect ancestry, frame initiator и resource type. Чтение тела ответа может закончиться после начала другого действия; это не меняет принадлежность. Значения остаются в памяти записи, авторизация экспортируется зашифрованной.

Analyzer декодирует URL-encoded с объявленной кодировкой, JSON включая вложенные массивы, text multipart, Unicode/HTML escaping. Строит граф переноса identity/token из JSON или заголовка ответа в тело/путь/query/header следующего запроса. Время проверяет порядок, но не доказывает зависимость. Поддержаны title/body в разных запросах и финальный publish без контента после обновления черновика.

Learner создаёт сценарий только из обмена текущего сайта. Hidden/meta/JSON/header/cookie извлекаются заново; числовые JSON ID сохраняют тип. Динамические пути/query используют URL escaping. Необъяснённый ID/nonce/hash/токен остаётся UNKNOWN_DYNAMIC. Сессионные значения не фиксируются в URL; cookie-auth проверяется отдельным HTTP-тестом. Сохраняется User-Agent браузерной сессии, поскольку некоторые форумы привязывают к нему авторизацию. Для timestamp-based form tokens соблюдается обычная пауза перед отправкой; проверки сервера не изменяются.

Runtime не импортирует Playwright или recognition. Schema v1 дополнена extraction `header` и `cookie`; старые проекты читаются прежним образом. Новые распознанные проекты ограничены точным origin, включая порт, и не исполняются до HTTP_VERIFIED. Проверка HTTP после браузера использует другой заголовок и другой текст и отдельное согласие. GUI добавляет отдельную пометку автоматически.

## Контроль действий и подтверждение

Survey разрешает same-origin чтение и блокирует мутации, WebSocket и service workers. Для выбранных точных CDN origins допускаются только статические GET; отдельный HTTP-клиент не переносит Cookie/Authorization/Referer, не принимает Set-Cookie в браузер и проверяет каждый redirect. Другие сторонние fetch/navigation блокируются. Дополнительные static origins задаются явно через API, без wildcard. Для login предусмотрено отдельное согласие на один POST показанной same-origin формы за две минуты.

Согласие на публикацию открывает ограниченную транзакцию: до шести POST/PUT/PATCH, точный origin, первая операция содержит разрешённый контент, следующие имеют доказанную зависимость от принятого ответа. Несвязанные фоновые записи и повтор одинакового запроса блокируются. Оpaque/пустой первый draft, мутации до ввода и другие не объяснённые операции требуют отдельного адаптера или обучения, а не общего снятия ограничений.

Успех требует GET постоянной ссылки, обоих текстов в опубликованной области и отсутствия login/error/hidden/editor подтверждения. Явный отказ имеет приоритет над permalink. Разделены publication_confirmed, publication_rejected, auth_expired, permalink_missing, workflow_not_built и HTTP unknown/failed. UNKNOWN не повторяется. Проверка не может доказать, что сервер с некорректной семантикой GET не создаёт побочные эффекты; известные опасные GET-маршруты блокируются.

Ключ из `POSTER_SESSION_KEY` имеет приоритет. Desktop повторно использует прежний `$HOME/.poster/session.key`, если нового ключа нет. Если существуют оба разных ключа, новый остаётся основным, старый используется только как локальный fallback дешифрования; ни один файл не перезаписывается. В общей библиотеке ключей нет.

## Оставшиеся границы

Закрытый Shadow DOM, cross-origin iframe/SSO, произвольные JS-преобразования/шифрование, localStorage-only auth, бинарные uploads и повторяющиеся form/multipart поля требуют адаптации. JSON-массивы поддержаны. Полный browser → HTTP на Windows и оригинальные сборки всех редакторов/коммерческих CMS требуют отдельной проверки; native Windows UI/clipboard smoke включён в CI. CAPTCHA, антибот-защита, доступ и модерация не обходятся. Никаких тестовых публикаций на чужих публичных форумах не выполнялось.
