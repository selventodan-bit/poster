# Poster 2.0: архитектура, аудит и границы

Основа — актуальный main на `3ca4ad7`, включая последние исправления clipboard. Старые HTTP Runtime, Engine, Project, Build/export, Drive, SQLite и генератор сохранены. Ветка разработки отделена от main.

## Аудит исходного поведения

Legacy builder сравнивал два ASCII-маркера с сырым телом одного POST/PUT/PATCH. Он мог пропустить percent-encoded Unicode, JSON-экранирование, multipart, rich HTML и раздельные запросы. Захват не содержал request/response ID или границ действия; ошибка «Expected one write request containing both markers» не доказывала необходимость браузерного исполнения. UI требовал ручного обучения и технического CSS до первого анализа. Эти ограничения обходятся новым потоком анализа декодированных наблюдений, а не заявлением о невозможности HTTP.

## Компоненты

- `EngineDetector`: расширяемые версионированные сигнатуры по нескольким признакам. Есть кандидаты XenForo/phpBB/vBulletin/MyBB/Discourse/SMF/Invision/Flarum/WordPress/wpForo. Это идентификация, не доказанная поддержка API этих продуктов.
- `UniversalFormDetector`: labels/ARIA/placeholder, тип и расположение поля, несколько форм, стандартные submit и кнопки по смыслу, contenteditable, same-origin iframe. Может открыть узнаваемое действие «Новая тема»; запросы, изменяющие данные, в исследовании блокируются. Не выполняет произвольное блуждание по сайту.
- `Recorder Capture`: прежний захват дополнен временем, request ID, response association, resource type, redirect provenance и action ID. Сырые тела и сессия живут в памяти; экспорт — только шаблоны и encrypted session.
- `NetworkAnalyzer`: сначала декодирует form/JSON/text-multipart. Для разделённых title/body требует общий action ID, порядок и перенос идентификатора из ответа предыдущего запроса в следующий. Время само по себе недостаточно. Непонятная связь → UNLINKED_REQUESTS.
- `HTTPWorkflowLearner`: использует Build/export schema-v1. Контент становится переменными, hidden/meta — CSS extraction из свежего GET, JSON-поля — JSON-path extraction, динамические ID — значениями ответа предыдущего шага. Неизвестный token/nonce/hash не фиксируется как константа. Наблюдаемые JSON/AJAX permalink превращаются в read-result + title/body VERIFY.
- `RecognitionSession`: один жизненный цикл браузера, read-only gate, отдельное согласие для браузера и HTTP, один attempt на канал, остановка и закрытие. Дубликаты одинаковых browser writes блокируются. Первый успех подтверждается GET по постоянной ссылке через HTTP с host/redirect gate; это не оптимистическое сообщение в DOM. Второе действие идёт через существующий Runtime.
- `KnowledgeBase`: отдельная локальная SQLite, закрытая модель Rule. Хранит digest ID, версию, алгоритм из enum, область, редактор, роли/позицию title, источник, названия проверок и счётчики. Не хранит сайт, контент, selectors, cookies, пароль или токены. Демонстрированное положение поля может разрешить неоднозначное сопоставление на другой форме. Это кандидат, который всё равно требует отдельного теста.

## Уверенность и состояния

Engine/form/fields/publication/result и http_verified независимы. Числа — эвристические оценки, не статистически калиброванные вероятности. Знакомый движок или применённое правило не повышает result/http без реальной проверки.

`DETECTED → BROWSER_VERIFIED → HTTP_CANDIDATE → HTTP_VERIFIED`; альтернативы — LEARNING_REQUIRED, FAILED, UNKNOWN. HTTP-кандидат экспортируется только с REVIEW и явным подтверждением. Для новых проектов недостаточно вручную поменять status на HTTP_READY: Runtime и Registry также проверяют recognition evidence. Старые schema-v1 проекты без recognition читаются по прежним правилам. Никто не объявляет их задним числом HTTP_VERIFIED.

Результат browser теста подтверждает только наблюдавшуюся публикацию. HTTP-тест — второе реальное действие, требует отдельного согласия или запуска на локальном fixture. UNKNOWN не возвращается автоматически в очередь. Неопределённую попытку нельзя повторить в текущей сессии; перед новым явным тестом оператор должен проверить сайт.

## Безопасность и ограничения

Browser route проверяет hostname, запрещает HTTPS downgrade, чужие запросы и mutating методы во время исследования; service workers и WebSocket отключены. Сессии экспортируются с фильтром доменов, ключ вне проектов. HTTP использует прежние redirect/cookie ограничения. Ручной вход и отправка включаются только после согласия. GET считается read-only по протоколу; проект не может гарантировать, что чужой сервер не создаёт побочных эффектов в GET.

Поддержаны локально проверенные HTML/AJAX/JSON/text-multipart формы, rich editors, iframe, csrf и связанная цепочка draft-ID → publish. Не заявляются произвольные JS-вычисления, cross-origin SSO/iframe, сложные shadow DOM, бинарные файлы, повторяющиеся поля, произвольный граф зависимостей, истекающий JS-localStorage auth или автоматический repair. Динамические query-параметры и непонятные token sources требуют review. HTML bodies сохраняют escaping через ограниченный `|html`; `|url` также поддержан без eval/Jinja.

На публичный проблемный форум запросы публикации не отправлялись. Live-CMS адаптеры, настоящий Windows GUI и hosted notebooks остаются отдельной проверкой. Массовое размещение, обход CAPTCHA/доступа/модерации не реализованы.
