Poster 3.0 — ProjectMaker + Dispatcher, этап 5B (Windows 10/11 x64)

DISPATCHER (Full): двойной щелчок PosterDispatcher.exe или кнопка Dispatcher в Maker.
Добавить проект… → выбрать сохранённый .postergraph.json → В очередь → заполнить
входы/timeout → Запустить обслуживание. Настройки workers применяются после
остановки обслуживания. История / результат проверяет SHA256; рабочая папка открывает файлы.
Закрытие окна НЕ останавливает задания. Для явной остановки — Остановить приём
(дождаться активных) либо Завершить службу. Следующий запуск окна подключается к службе.
UNKNOWN / Нужна ручная проверка не повторяются автоматически: проверьте внешний сайт.

УДАЛЁННЫЕ WORKERS (5B, Full): «Подключить Linux Agent пошагово…» проверяет TLS,
экспортирует приватный offer на 15 минут, сверяет Agent fingerprint перед импортом
и отдельно запрашивает доверие. ONLINE требует подписанного heartbeat; тестовый
граф возвращает файл и SHA256. Установка Linux/systemd, ошибки и пределы:
docs/POSTER_STAGE5B_REMOTE_DEPLOYMENT.md. Windows/Linux cross-host пока NOT_EXECUTED.

Прежний ручной workflow 5A: в отдельной вкладке экспортируйте публичную
идентичность Controller, загрузите registration.json Linux Agent и приватный
controller-relay.json, сравните полный ID и явно подтвердите доверие. Agent и
Controller подключаются исходящим HTTPS к отдельно развёрнутому TLS relay.
Выбор Local/конкретного Agent появляется в формах задания и расписания.
Старые расписания остаются локальными. Offline Agent не заменяется другим worker.
Удалённая машина получает необходимые секреты в памяти; Windows queue.key не передаётся.
Отзыв доступа останавливает новые выдачи, неопределённые эффекты требуют проверки UNKNOWN.
Windows browser profile не переносится; для Linux используйте новую сессию.
Инструкция: docs/POSTER_STAGE5A_REMOTE_LINUX_WORKER.md в GitHub.

РАСПИСАНИЕ (Full): добавьте проект → вкладка «Расписание» → Создать… → выберите
проект/версию, режим, timezone и местное время → Сохранить → подтвердите входы.
Работает однократно, через интервал, ежедневно и по выбранным дням недели.
Сохранение запускает обслуживание. GUI можно закрыть: служба остаётся отдельным процессом.
Проект и защищённые входы закреплены; изменение исходника Maker их не заменяет.
«Обновить версию…» — явная проверяемая операция. «Пауза» прекращает новые постановки,
уже принятые задания отменяются отдельно в очереди. История сохраняется после удаления.
По умолчанию старые пропуски не исполняются; можно догнать только одно последнее событие.
При DST повторяющийся час запускается один раз, несуществующее календарное время пропускается.
UNKNOWN/REVIEW_REQUIRED приостанавливает автозапуски проекта. После фактической ручной
проверки используйте «Проверено: возобновить»; неопределённые статусы сохраняются.
Автозапуск при входе Windows включается только кнопкой с явным согласием. Его можно
проверить и отключить в этой же вкладке. Используется Task Scheduler текущего пользователя,
без пароля и прав администратора. После перемещения EXE включите автозапуск заново.
Компьютер должен быть включён, пользователь должен войти в систему.
Подробнее: docs/POSTER_STAGE4B2_SCHEDULER_MONITORING.md в GitHub.

Очередь и ключ находятся в %LOCALAPPDATA%\Poster\Dispatcher, отдельно от старой .poster.
Перед переносом/обновлением EXE завершите службу; сохраните обе папки данных.
Для защищённого проекта выбирайте существующий session.key Maker, новый не создавайте.
CSV/XLSX и прочие входные файлы автоматически не переносятся: workdir задания пуст.
Создавайте файлы графом или передавайте их содержимое входами; абсолютные пути Maker запрещены.
Browser-кубики worker используют установленный Chrome/Chromium/Edge; без браузерных
кубиков браузер не запускается. Компоненты автоматически не скачиваются.
PosterService.exe и PosterWorker.exe — внутренние процессы; вручную их не открывайте.
Не удаляйте _internal, BUILD_INFO.json и другие EXE: runtime общий, процессы независимы.
Lite сохраняет прежний интерфейс; новый Dispatcher GUI доступен в Full.
Подробнее: docs/POSTER_STAGE4B1_DISPATCHER_GUI.md в GitHub.

1. Распакуйте ВЕСЬ внутренний poster-maker-windows.zip (Full) или poster-windows.zip (Lite). _internal должен остаться рядом с Poster.exe.
2. Дважды щёлкните Poster.exe. Python, PowerShell, Git и Docker не нужны.
3. Нажмите «Демо-сайт», затем «Пример с циклом». Появится готовый небольшой проект
   с переменными, For Each, Compare, Break/Continue, Switch и чтением результата.
4. Выберите Browser.Input, нажмите «Точка останова», затем «Запустить».
   Задайте вход prefix и подтвердите выполнение. На паузе измените текст кубика,
   например «Исправлено: {{note}}», и нажмите «Применить».
5. Справа в «Переменных» видны начальные и текущие значения. «Задать» сохраняет
   определение в проекте, «Задать в отладке» меняет только текущий run.
6. «Шаг» исполняет кубик и продвигает указатель; «Выполнить кубик» делает выбранное
   действие в текущем браузере, сохраняя указатель. Эти действия могут отправлять формы.
7. Снимите breakpoint и нажмите «Запустить». Демо выполняет две публикации,
   counter становится 2, last_text содержит прочитанный результат.
8. Сохраните, закройте и откройте приложение. Граф загрузится; новый запуск
   сам поднимет демо-сервер и создаст изолированные значения переменных.

Full Maker: браузер, граф, свойства, переменные и конструктор находятся в одном окне.
Запись: введите URL в браузере, откройте страницу Enter, нажмите «Начать запись».
Выполняйте действия в верхней панели браузера. В Lite браузер открывается отдельно. «Остановить запись» сохраняет браузер. Выберите кубик и нажмите
«Продолжить запись», чтобы вставить новый участок после него, сохранив граф.

«Элемент»: открыть браузер по URL, выбрать элемент, посмотреть атрибуты,
проверить CSS/XPath с подсветкой, перенести селектор в кубик или добавить чтение
текста/атрибута в переменную. Есть базовое управление вкладками.

Подстановка: {{name}}. Значения: текст либо JSON (12, true, ["a","b"]).
Пароли записываются secret_ref; секреты хранятся зашифрованно рядом с графом,
ключ отдельно в .poster/private. Не передавайте другим людям .poster и секреты.
Граф v1 загружается с миграцией; при явном сохранении создаётся *.v1.bak.

Два пакета: poster-windows (Lite) использует установленный Chrome/Chromium/Edge;
poster-maker-windows (полный Maker) включает QtWebEngine и по умолчанию выбирает qt.
Полный пакет больше, браузер уже внутри; ни один пакет не скачивает компоненты сам.
Full Maker использует единый Qt-интерфейс. Lite сохраняет проверенную Tk-оболочку.
Браузер: URL, назад/вперёд, обновить, вкладки/popup и масштаб.
Холст: Ctrl+колесо — масштаб, средняя кнопка — перемещение, Ctrl+D — копировать,
Ctrl+Z/Ctrl+Y — отменить/повторить. Есть поиск кубиков и именованные выходы.
Панели можно изменять разделителями; расположение сохраняется после закрытия.

Запись сохраняет контекст вкладки и iframe. Не удаляйте создающий вкладку NewTab
или вызывающий popup Click/WaitPopup, если последующие действия используют эту вкладку.
«Элемент» показывает вкладку, iframe, CSS/XPath; поддержаны Клик/Ввод/Ожидание.
Профили: до открытия браузера выберите или создайте профиль. «Сохранить сессию»
явно шифрует cookies/localStorage. «Остановить» закрывает браузер; затем можно
переименовать, сменить, очистить или удалить только выбранный профиль. Ключи и профили остаются в .poster,
в проекты/Drive не экспортируются. IndexedDB/sessionStorage пока не сохраняются.
Нет полного браузерного дерева и поддержки всех браузерных диалогов. Подпроекты поддерживают HTTP/данные/файлы без общей браузерной сессии.

Poster 2.0 сохранён во вкладках «Сайт и обучение», «Проекты», «Очередь», «Результаты»
и «Система». Новый граф не заменяет старые Workflow v1 / READY-проекты.
Перед обновлением закройте Poster и сохраните резервную копию .poster.
Подробности: docs/PROJECTMAKER_3_STAGE3B1.md и docs/ZENNO_PARITY_MATRIX.md в GitHub.
SHA256 внутреннего ZIP находится рядом с ним в Actions artifact.

Компоненты и лицензии: THIRD_PARTY_NOTICES.txt и каталог licenses.

Этап 3B.2: 78 действий (было 29). Full: «Примеры 3B.2…» → выберите HTTP/JSON,
список/цикл, CSV/Excel или подпроект. Для HTTP встроенный тестовый API запускается
сам, вход api_base уже заполнен — подтвердите значение. Браузерная сессия графа
для этих примеров не запускается. В самом Full GUI видимый Qt-браузер остаётся частью окна.

«Проект»: выберите рабочий каталог файлов. По умолчанию — отдельный каталог
проекта в .poster/maker-data. Относительные пути переносимы; выход за каталог и
ссылки запрещены. Перезапись требует настройки кубика. «Открыть каталог» показывает
результаты без терминала. Lite: вкладка «Проект» позволяет выбрать тот же каталог.

«Результат»: JSON и предпросмотр таблиц/списков. Выбор переменной также обновляет
предпросмотр. Защищённые значения скрыты. Полные данные сохраняются кубиками в файлы.
Для Project.Run выходы дочернего графа объявляются во вкладке «Проект».

Примеры также находятся в examples/maker-stage3b2 рядом с Poster.exe.
HTTP: TLS включён, повторной отправки нет, cookies изолированы от других запусков
и BrowserProvider. Ответ защищён по умолчанию. Excel не вычисляет формулы; читает
только cached values. Обновление существующей книги и замена листа разрешаются отдельно.
Подробный контракт: docs/PROJECTMAKER_3_STAGE3B2.md в GitHub.

Этап 5C — Google Drive и автономные notebook:
Меню Google Drive в Maker: подключить, сохранить, открыть, обновить, папка и история.
При первом подключении выберите OAuth Desktop app JSON и разрешите вход в браузере.
Tokens копировать не нужно; они защищены DPAPI текущего пользователя Windows.
Файлы CSV/XLSX/JSON добавляются только после явного выбора; укажите возвращаемые файлы.
В Dispatcher → Google Drive… можно открыть закреплённую версию, подготовить общий
Colab/Jupyter или Molab Launcher и синхронизировать отдельные результаты каждого запуска.
«Всего запусков» и «Одновременно» — разные настройки. Для пяти параллельных копий
также установите max_workers и max_per_project не меньше 5 до запуска службы.
Notebook работает в автономном режиме DETACHED; Windows может быть выключен.
Local/Remote managed jobs и расписания по-прежнему требуют работающего Controller.
После неопределённого POST повтор автоматически не выполняется.
Демо: examples/maker-stage5c. Launcher: notebooks/Poster_Launcher.ipynb и Poster_Molab.py.
Инструкция: docs/POSTER_STAGE5C_DRIVE_CLOUD_MULTIWORKER.md.
Для free Colab/Molab показан ручной интерактивный workflow с параллельностью 1.
Автоматическое выделение платных ресурсов выключено. Реальные аккаунты провайдеров
в CI не использовались; HTTP Drive fixture не является живым Google Drive E2E.
